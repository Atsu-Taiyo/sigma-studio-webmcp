# AI作業センター（Task Queue）計画

この計画は、アプリ内のAI編集セッションを「統合管理」するための設計メモです。現状はセッションごとの一時UI状態にAIの実行状態と提案が乗っているため、並列実行できず、提案中のものが消え、今何が起きているか把握しづらい。これを **タスクを永続管理し、セッションは使い捨てる** モデルへ作り替える。

## 現状の課題

- **統合管理場所がない** — タスクを置く永続ストアがなく、AI作業が各UIに散らばっている。
- **並列できない** — 1セッション=1UIに密結合しており、複数のAI編集を同時に走らせられない。
- **提案中のものが消える** — 提案がコンポーネントのstateに乗っているため、ウィジェットを閉じる/再描画すると蒸発する。
- **今何が起きているか把握しづらい** — タスクのライフサイクル状態が一元化されていない。

根本原因は「AIの実行状態と提案がUIの一時状態に乗っていること」に集約される。

## 方針

セッションを管理するのではなく、**タスクを管理してセッションは使い捨てる**。CursorのagentタブやCIのジョブ一覧に近い。小さなタスクを次々と投入し、ワーカーが裏で並列に回し、結果が提案として溜まり、ユーザーがまとめて（あるいはその場で）レビューする、という流れを基本形にする。

3層構成：

```
[Task Store]  永続。1タスク = {id, anchor, intent, provider, status, proposal, error, ...}
     ↓ 状態: queued → running → proposed → applied / discarded / failed
[Scheduler]   並列度を制限したワーカープール。キューをドレイン。
              同一ブロックアンカーに当たるタスクは直列化。
     ↓
[Dock UI]     全タスクを status ごとに表示。提案はいつでも開いて適用/破棄。
              本文には承認済みのものだけ反映。
```

### 1. 提案を Task Store に持たせる

最重要。提案を現在のインラインUIのstateから引き剥がし、Task Store のレコードに持たせる。これだけで「提案が消える」が直り、複数提案が同時に待機できる。既存の pending proposal（デスクトップ承認フロー）を、UI都合ではなく Store 主導に作り替える。

### 2. タスクはブロックアンカーに紐づける

overlay anchoring と同じ発想で、タスクを block anchor に紐づける。本文がreflowしても提案が正しい位置に戻れる。

### 3. インラインと Dock は同一タスクの別ビュー

**全編集（単発インラインも含む）を Task Store に積む。** インラインは Store 上の1タスクを「カーソル位置にレンダリングしたビュー」にすぎない。`apply` / `discard` はタスクに対する操作で、インラインから撃っても Dock から撃っても同じレコードを変える（＝適用可否はクライアントが選ぶ）。

インラインを「Storeに積まない特別扱い」にすると、提案がUI stateに戻って消える病が再発するため、単発も必ず Store を経由させる。

```
選択 → AI編集（入力欄、PR #187）
   ↓ Task を1件 create（status: queued）
   ↓ 投入と同時にインラインに作業中ウィジェット表示（＝そのタスクのライブビュー）
   ↓ ワーカーが回す → status: proposed、proposal が Store に入る
   ↓
   ├─ その場で適用/破棄        ← インラインから task.apply() / task.discard()
   └─ ウィジェット閉じても Store に残る → Dock から後で適用/破棄
```

UX上の注意は1点：**単発の体感を重くしない**。投入→即ウィジェット→その場で適用、の流れは現状のPR #187のままに見せ、裏で Store に乗っているだけにする。Dock は「溜まっているもの／閉じても残っているもの／並列の全体像」を見るために開くときだけ使う。

## 確定事項

| 項目 | 決定 |
|---|---|
| スコープ/永続 | ワークスペース横断・ローカル（templates v1 と同じ路線） |
| 競合 | 同一ブロックアンカーは直列化（重なるタスクは順番待ち） |
| UI | インラインも Dock も同一 Task の別ビュー、Store が SSOT |
| 並列 | 異なるアンカーのタスクはワーカープールで並列ドレイン |
| プロバイダ表示 | 内部は Codex/Claude、ユーザー向けは「ChatGPT」/「AI」ブランディングを維持 |

## タスクレコード（最小形）

```ts
type AiTask = {
  id: string
  workspaceId: string
  documentId: string
  anchor: BlockAnchor          // overlay anchoring と同じ仕組みを流用
  intent: string               // ユーザー入力 "この段落を簡潔に" 等
  provider: 'chatgpt' | ...    // 内部は Codex/Claude、表示は AI ブランディング
  status: 'queued' | 'running' | 'proposed' | 'applied' | 'discarded' | 'failed'
  proposal?: EditProposal      // 提案本体。ここに持たせるのが肝
  error?: string
  createdAt: number
}
```

## 段階的な進め方（案）

1. **コア（Task Store + Scheduler）を薄く通しで作る。** 別worktreeで、永続ストアと並列度制限つきワーカープール、同一アンカー直列化までを最小実装。
2. **インラインを Store に繋ぎ替える。** PR #187 の作業中ウィジェットを、Store 上のタスクのライブビューに置き換える。この時点で「提案が消える」がコア側で直る。
3. **Dock UI を後追いで追加。** 全タスクの一覧・status別表示・後からの適用/破棄。

Dock UI は後回しでも、消える問題と並列実行はコアとインライン繋ぎ替え（1〜2）で先に解消する。
